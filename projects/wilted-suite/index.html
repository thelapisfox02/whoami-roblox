WiltedSuite

Properties
RoleInternal development suite
AuthorshipAI-assisted
Key number4 public modules, MIT

A core plus services I use for internal development: monetization, limited stock, inventory, and telemetry. I start the scripts, write the recipes and design decisions, use AI to expand and improve, and nothing ships until it passes my own QA. Each service is game-blind: the game supplies its own wiring, and a service that finds no core installed disables itself with one warning instead of erroring.

  • WiltedCore (private, documented only) has 13 modules: logging, signals, remotes, config, retry and a service directory. Its suite passes 40/40 (169 checks), and server and client output are identical.
  • Stock claims from a finite pool with idempotency keys and rollback, so a limited drop's public count stays honest.
  • Monetization holds a product catalogue, purchase rules and grant kinds that the game registers. A receipt that cannot be granted yet is left unconsumed and retried.
  • Inventory is an inventory and hotbar GUI independent of Roblox's default backpack. It has categories (icon, limit), and its layout can be rearranged in Studio without touching code. The public copy leaves out the GUI templates.
  • Harvest is telemetry. It receives events after the game commits them, drops duplicates by event id, keeps per-player summaries and hands them to storage and sinks. It never grants, prices or changes game state, and game-specific adapters live outside the package. The repository includes the adapter from Roll Gems for Money as an example.

Every change comes with a written plan, numbered decisions, phase reports, before/after baselines and drop-in tests.

Monetization, Stock, Inventory and Harvest are public under the MIT licence, with a README for each. The core is private: its API is documented, its source is not. WiltedSuite on GitHub · core documentation.
